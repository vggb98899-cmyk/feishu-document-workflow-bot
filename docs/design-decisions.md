# 设计决策

## 使用长连接而非公网 Webhook

长连接减少了公网域名、证书和回调服务的部署成本，适合单机内部机器人。代价是必须处理连接断开、进程守护和单实例问题。

## 使用 SQLite 而非消息中间件

当前部署规模是单机单实例。SQLite 能同时提供持久队列、唯一键幂等和 operation 状态保存，维护成本低。若未来需要多机并发，应迁移到支持事务和分布式并发控制的共享数据库。

## 不自动重试未知外部写入

网络超时不等于写入失败。自动重试 CREATE、COPY 或 Owner Transfer 可能生成重复文档或重复修改权限，因此 UNKNOWN/AMBIGUOUS 默认进入人工核验。

## CREATE 与 COPY 使用独立 Gate

两个功能的风险和上线节奏不同。独立开关避免开发中的 COPY 影响已经稳定运行的 CREATE。

## COPY 统一进入配置目录

公开版本不依赖源文档父目录解析。应用只验证源 docx 可访问，副本目标使用明确配置的目录 Token，并禁止回退到根目录或未知目录。

## Owner Transfer 单次尝试

明确 SUCCESS 即记录成功；超时或进程崩溃时不主动重复调用。这个选择优先避免重复副作用，代价是部分异常需要人工确认。
